# quant_trading_v2 — D1 型態 × 量能 × M1 日內型態 掃描

目標: 用 D1 (日 K 型態、量能) 先選股票日, 再用 M1 (開盤區間、急拉/急殺、突破、VWAP 相對位置) 決定進場, 13:30 收盤出場, 系統性找出
扣除成本 **且處理漲停鎖死** 後仍穩定獲利的「D1 型態 × M1 觸發 × 多/空」組合。

資料: `data/d1`, `data/m1` 是 macOS 替身 → 實際在 `../quant_trading/data/raw/` (D1 2018-01~2026-10, M1 2020-01~2026-10, 月 parquet)。
`scripts/config.py` 直接指向實際路徑。

## 目錄
```
scripts/config.py                 路徑、成本 (0.23%)、universe 門檻、探索/驗證切點
scripts/01_build_d1.py            D1 合併 + 特徵 + 37 種型態標籤 -> data/processed/d1_feat.parquet
scripts/02_build_m1_daily.py      M1 -> 每檔每日日內摘要 (universe 內) -> data/processed/m1_daily/YYYY_MM.parquet
scripts/03_scan.py                37 型態 × 27 觸發 × 多/空 掃描 -> stats/scan_all.csv, stats/pattern_scan.md
scripts/04_o05_short_deepdive.py  掃描冠軍深入檢驗 -> stats/o05_short_deepdive.md
```
執行順序 01 → 02 (約 1.5 分, 5 process) → 03 (10 秒) → 04。

## 設計
- **Universe**: 前 20 日均成交額 ≥ 1 億、昨收 ≥ 10、上市/上櫃、4 碼代號、排除 ETF → 每日約 390 檔。
- **D1 型態** (全部只用前一日以前的資料; gap 類用今日開盤): 突破 20/60 日高 ± 放量、長紅/長黑爆量、漲停 (首根/連兩根/摸到沒鎖)、跌停、盤整收斂 ± 突破、連漲/連跌 3 日、多/空頭排列、量縮、爆量長上/下影、錘子/流星、跳空 ±3%、高/低 ATR、20 日大漲/大跌、20 日區間頂/底、大盤跳空 ±1%。
- **M1 觸發**: 09:00~09:02 VWAP 開盤進、09:30 / 10:00 定時進、開盤 5/15/30 分區間向上/向下突破 (12:00 前 / 10:00 前)、09:30 強/弱勢 (區間位置+VWAP+開盤)、開盤 30 分 ±2%、開盤 5 分 ±1% 且放量、跳空回補、10:00 守住高/低點、10:00 在 VWAP 上/下拉回。
- **結算**: 出場一律 13:30 收盤競價, 來回成本 0.23%。**現實規則 (v1 教訓)**: 空單進場後到昨收 +8% 立即回補 (+0.2% 滑價)、收盤仍鎖漲停額外 −7%；多單對稱；進場前已到 ±8% 或摸到漲跌停不進。同時列「天真」數字 (收盤出、不處理漲跌停) 供對照。
- **驗證**: 探索期 2020-01~2023-12, 驗證期 2024-01~2026-10, 排名用兩段 t 值 (以每日平均報酬計) 的較小者; 樣本門檻 探索 ≥300 筆、驗證 ≥200 筆。


## 主要發現 (2026-10-24; 細表: stats/pattern_scan.md, stats/o05_short_deepdive.md, stats/family_portfolio.md)

### 1. 天真掃描會被漲停鎖死騙
不處理漲跌停、單純「進場 → 13:30 出」時，冠軍是 **開盤 5 分急拉 ≥1% 且放量 → 放空** (`o05_up1_vol short`)：全 universe 每筆 +0.68% / +0.45% (探索/驗證)、每日 17 檔、7 年全正、疊上任何 D1 強勢型態 (漲停、跳空、20 日大漲、高 ATR) 都到 1% 以上。
但這些交易 **8% 收盤鎖在漲停、31% 盤中到過 +8%**。加入 v1 的現實規則 (+8% 強制回補、鎖死 −7%) 後每筆掉到 **+0.04%**，驗證期為負。
強制回補門檻越鬆越好 (+9.5%: 0.23%)、鎖死罰金若只有 2% 則 0.33%——也就是這條訊號的「獲利」大部分是承擔漲停風險的補償，不是 alpha。
細分: 平開 (|gap|<1%) 再急拉 +0.19% (勝率 56%、強制 20%)；跳空開高 ≥2% 再急拉 −0.12% (強制 57%)；5 分最高已 ≥ 昨收 +5% 的 −0.09% (強制 62%)。**結論: 開盤急拉放空只能做平開的，且不能疊漲停/大跳空股。**

### 3. 一個有邏輯的家族: D1 過熱 × M1 開盤區間向下突破 → 空
把 D1「過熱」(跳空 ≥3%、流星線、昨日漲停、長紅/爆量、20 日大漲) 與 M1「開盤 5/15/30 分區間向下突破」組起來，每筆 0.1~0.4%、勝率 54~60%、**強制回補率只有 2~20%** (比開盤追空的 30~60% 低很多，因為進場時股票已經轉弱)。
最大貢獻者: 流星線 × 5 分區間向下突破 (10:00 前): 15,331 筆、每筆 0.33%、勝率 58%、強制 4%。

### 4. 對「D1 型態 + 量能 + M1 型態」這個題目的結論
1. 台股日內的系統性漂移在空方 (全 universe 開→收 −0.26%)，D1 型態主要決定「漂移多大」，M1 型態主要決定「進場價多好」和「要承擔多少漲停風險」。
2. 量能的作用是雙面的: 昨日放量 / 開盤放量的股票空單每筆較高，但強制回補率也成比例上升，扣掉後淨效果接近 0。「量」在這裡是波動的代理，不是方向。
3. 唯一在現實結算後還能跨期間成立的 M1 型態是 **「開盤區間向下突破」**(確認轉弱後再空) 與 **「流星線隔日開盤空」**，兩者每筆 0.2~0.4%。所有做多型態 (ORB 向上、守住高點、VWAP 之上拉回、跳空回補) 扣成本後都是負的。
4. 這些規則型組合沒有一個比 v1 的 LightGBM 模型好。合理的下一步不是再找型態，而是 **把「開盤區間向下突破時間/幅度」「流星線」當特徵或進場條件加進 v1 模型 (例如 v1 候選股等 5 分區間向下突破再空)**，用 v1 的 pipeline 驗證是否降低強制回補率。

## D1 三角收斂突破 (2026-10-24) — `scripts/07_triangle_blocks.py` → `08_triangle_blocks_backtest.py` → `stats/triangle_blocks_backtest.md`
三角定義 (與使用者逐步確認): 5 根 K 內最高/最低 = 擺盪高/低點；取最近 2 高 + 2 低，後高<前高、後低>前低；兩高點之間無其他高點、兩低點之間無其他低點；4 點時間交錯 (HLHL/LHLH)；中間 K 棒不穿線；昨收在線內；收斂比 (後段區間/前段) ≤ 0.8。universe 內 7 年 934 筆、2020 起有 M1 的 773 個三角日。
`plot_triangles2.py` 畫最近 N 檔供人工驗證 (`stats/triangles2_recent_*.png`)。較早的回歸線版 (`06_triangle_breakout.py`) 經圖形驗證不是交易員認的三角，已棄用。
- 三角日當天: 27% 向上突破上緣、28% 向下跌破下緣、46% 都沒有。向上突破後 30 分仍在線上只有 42%，收盤仍在線上 47% → 假突破過半。
- **向上突破做多 (當沖) −0.22%/筆 (137 筆, 勝率 41%)，波段持有 T+1/T+3/T+5 也是 −0.8 / −0.4 / −0.2%**：型態本身沒有多方 edge，不是當沖與否的問題。等 30 分確認再進更差 (−0.49%)。
- **向下跌破做空 +0.34%/筆 (154 筆, 勝率 58%, t 1.85)**，探索 +0.20 / 驗證 +0.47；下降高點 ≥3 個的子集 +0.72% (78 筆, 勝率 68%)。但樣本太少 (每 3 天不到 1 筆)，且與「開在三角內不等突破直接開盤空」(+0.12%) 相比只多 0.2%。波段持有 T+1~T+5 不比當日出場好。
- 結論: 三角收斂在台股是「跌破比突破可信」的型態，和整個市場空方偏多一致；但單靠它每天不到 1 筆，無法成為獨立策略。

### 突破後的延續 (2026-10-24) — `scripts/09_triangle_post_breakout.py` → `stats/triangle_post_breakout.md`
D1 2018~2026, 收斂比 ≤0.8, 同檔 14 日內只算第一次突破。事件: 向上突破確認 (收在上緣之上) 131、向上假突破 111、向下跌破確認 151、向下假跌破 86。
- **向上突破確認後 T+1~T+10 每天的開→收全部為負 (平均 −0.3%, 勝率 36~44%)**，累積收→收 10 日 +0.9% 全靠跳空 (每天 +0.3~0.6%)。「延續」只發生在隔夜，日內反而回落 → 順向當沖做多 T+1~5 每筆 −0.60% (653 筆)；逆向做空 ≈ 0。
- **向下跌破確認後 T+1~T+3 開→收 −0.5~−0.7%、仍在線下 70%**，T+4 起消失、T+10 累積回到 0。順向當沖做空 T+1~3 每筆 +0.31% (453 筆, 勝率 54%, t 2.4)，T+1~5 掉到 +0.09%。
- 假突破 / 假跌破之後沒有可交易的方向 (各方向 |每筆| ≤ 0.13%)。
- 結論: 三角突破後的方向性只有「跌破 → 之後 3 天內日內偏空」可用，向上突破的延續只在跳空、抓不到日內。

### 突破後 3 日內出現明顯趨勢的機率 (2026-10-24) — `scripts/10_trend_probability.py` → `stats/trend_probability.md`
多種「明顯趨勢」定義 (3 日累積 ≥2/3/5%、盤中曾觸及 3/5%、3 日收盤全同側、3 日連續同向、3 日日內合計 ≥2/3%)，對照 universe 任意日與 ATR20≥3% 任意日的無條件機率。
- 向上突破確認後順向 3 日累積 ≥3% 的機率 24%，與 universe 基準 22% 幾乎相同，低於高波動基準 26%；逆向 ≥3% 也有 23%。盤中曾觸及 +3% 54% vs 高波動基準 56%。
- 向下跌破確認後順向 3 日累積 ≤−3% 28% vs 高波動基準 27%；3 日日內合計 ≤−2% 40% vs 高波動基準 42.5%。
- 假突破 / 假跌破之後順向與逆向機率都在 23~35% 之間互相抵銷。
- **結論: 三角突破不改變「3 日內出現明顯趨勢」的機率，所有數字都落在同波動度股票的無條件機率附近 (±3 個百分點)。** 前一段看到的「跌破後 3 天日內偏空」是幅度上的小偏差 (每天 −0.5%)，不是趨勢發生機率的提高。

### 突破日量比 × 離線距離 (2026-10-24) — `scripts/11_breakout_quality.py` → `stats/breakout_quality.md`
- 向上突破確認 (131): 量比中位只有 1.2，離線中位 1.2%。切量比 (<1 / 1~2 / 2~3 / ≥3) 順向 3 日 ≥3% 機率 20 / 30 / 22 / 33%，逆向 16 / 30 / 30 / 11%，沒有單調關係。離線 1~3% 這格最好 (順向 35%、逆向 16%、T+1~3 日內合計 +0.3%, n=37)，但離線 ≥3% 又變差 (29% vs 34%)，像是雜訊。量比 ≥2 ∩ 離線 ≥2% 順向 29% / 逆向 33%。大 K (≥5%) 突破後順向與逆向都 33%：只是波動大。
- 向下跌破確認 (151): 跌破多在量縮時發生 (量比中位 0.6, 只有 1 筆 ≥2)。量比 <1 的順向 32% / 逆向 22%、T+1~3 日內合計 −2.1% (做空為正, 勝率 64%)；量比 1~2 反而順向只有 15%。離線 ≥2% (41 筆) 順向 34% / 逆向 22%、T+1 日內 −1.3% (72% 為負)；大 K 跌破 (17 筆) 順向 41%、T+1~3 日內 −2.9%。
- 結論: 向上突破切任何條件都拉不開順向與逆向 (差距 ≤ 6 個百分點, 每格 n 20~70)。向下跌破「量縮 + 收盤離下緣 ≥2%」順向 34% vs 逆向 22%、之後 3 天日內偏空 −2.4%，方向最一致，但只有 41 筆。

### 突破後第一個 MACD 柱狀體背離 (2026-10-24) — `scripts/12_macd_divergence.py` → `stats/macd_divergence.md`
D1 MACD 12/26/9。向上突破確認後找第一個頂背離 (柱狀體正峰變矮、價格創高)，向下跌破後找第一個底背離；峰/谷隔天確認 = 訊號日 D。30 日內出現率約 32~35%，中位在突破後第 14 日；訊號日價格已離突破日 +10% / −7%，85~93% 仍在線外。
- 頂背離後 (46 / 74 筆, 收斂比 ≤0.8 / 不限): 5 日累積 +0.9% / −0.6%，累積 ≥+3% 25% / 23% vs ≤−3% 28% / 32%；順向做空當沖 T+1~3 每筆 −0.1% / +0.1%；做多 −0.7% / −0.8%。
- 底背離後 (58 / 108 筆): 5 日累積 −0.6% / −0.2%，≥+3% 33% / 34% vs ≤−3% 39% / 37%；順向做多當沖 T+1~3 −0.7% / −0.5%；做空 0.0 / −0.1%。
- 結論: 背離訊號後價格沒有反轉，兩個方向的 3~5 日機率各約 25~35%，與無條件相同；做多當沖照樣 −0.5~−0.8%/筆 (市場日內偏空)，做空 ≈ 0。D1 MACD 柱狀體背離在這個樣本沒有預測力。

## D1 過熱 × M1 開盤區間向下突破 → 空 深入 (2026-10-24) — `scripts/13_build_orb_dn.py` → `14_orb_dn_deepdive.py` → `stats/orb_dn_deepdive.md`, `orb_dn_daily.csv`
13 從 raw M1 對 universe 每個股票日算開盤 5/10/15/30 分區間、第一根跌破區間低的 bar (時間/價/量/累積成交額)、突破後 5/15/30 分價、收盤確認版、三種停損 (收回區間內 / 站回 VWAP / 突破區間高) 與 0.5/1.5/2 倍寬的停損高度, 含停損 bar 開盤價。
結算: 進場 = min(區間低, 突破 bar 開)；+8% 強制回補、鎖死 −7%、成本 0.23%；停損成交 = max(停損價, 該分鐘開盤) + 0.1% 滑價。

## 永豐模擬環境自動執行 + 滑價紀錄 (2026-10-27) — `scripts/paper_orb.py` + `.github/workflows/paper.yml`
目的: 量測實際滑價。回測假設在區間低成交, 滑 1 檔年均從 109 萬掉到 43 萬 (`stats/delay_drawdown.md`), 是否加「一檔 ≤0.15%」與部位配置都等這個數字。
選股與進出場規則完全沿用 `orb_live.py` (`build_pool` / `open_stage` / `range_stage` / `Book`: 每日最多 10 檔、每檔 30 萬整數張、先跌破先做、12:00 後失效), 只把訊號換成永豐**模擬環境**委託。
```
cron-job.org 08:50 → paper.yml: orb_live.py refresh (D1) → paper_orb.py run --publish
  09:02  MIS 開盤 → 候選; 登入 Shioaji(simulation=True), 訂閱候選逐筆 tick
  09:05  MIS 區間 → 監看名單 (同 live.yml); 每筆 tick 餵 orb_live.Book
         tick < 區間低 → 立即市價「現股當沖先賣」(daytrade_short); tick > 區間高 → 立即市價買回 (只買回券賣實際成交的張數)
  13:25  其餘部位以漲停價限價 ROD 買回 (13:25 起收盤集合競價不收市價單, v1 2026-10-27 實測 op_code 88) → 以收盤價成交
  13:35  結算 → HF db/orb/paper/
```
- **為什麼不是觸價單**: Shioaji (1.7.x) 沒有股票觸價 / 條件單 API, 所以是「tick 偵測 → 市價單」, 並記錄每一段延遲。
- 每一腳 (進場 / 停損 / 收盤) 記: 訊號價 (區間低 / 區間高 / 收盤價)、觸發 tick 價、tick 交易所時間、本機收到時間、委託時間、成交時間、成交價、滑價 (元 / 檔 / %)。**滑價正 = 對我們不利** (券賣: 訊號價 − 成交價；買回: 成交價 − 訊號價)；檔數用升降單位逐檔數 (跨 50 / 100 元級距也對)。拆成 **觸發滑價** (訊號價 → 第一筆跌破的 tick, 定義上至少 1 檔) + **執行滑價** (觸發 tick → 模擬成交價)。延遲: `detect_ms` (收到 − tick 時間)、`order_ms` (送單 − 收到)、`fill_ms`、`tick_to_fill_ms`。
- 輸出 `paper/<date>_trades.csv` (每檔: 狀態、券賣 / 買回價與時間、進出場滑價檔數、模擬報酬 `sim_net_pct`、回測口徑報酬 `ideal_net_pct` = 區間低進場 / 區間高×1.001 停損 / 收盤回補, 皆含成本 0.23%)、`_slippage.csv` (每一腳)、`_events.csv`、`_watch.csv`、`_summary.json`；`--publish` 上傳 HF `db/orb/paper/`, 並更新 `latest.json`、`live.json` (盤中每 3 分鐘 / 有事件即時) 與累計 `summary.csv` (每日一列)、`slippage.csv` (每一腳一列; 讀不到舊檔時不覆蓋)。
- 網頁「模擬單」分頁 (https://fade.just1stock.com/#paper): 讀 HF `db/orb/paper/` 的 `live.json` (今日部位, 盤中每 20 秒重讀)、`summary.csv` (每日清單與累計損益: 模擬成交 vs 訊號價) 與 `<date>_trades/_slippage/_events.csv` (逐檔: 訊號價 / 成交價 / 差幾檔, 每一腳的時間)。本機 `webapp.py` 讀 `paper/` (`--paper-dir` 可改, 例如 `paper/replay`); `write_day` 也會在本機維護一份累計 `summary.csv`。
- 安全: `Shioaji(simulation=True)` 寫死、常數 `SIMULATION=True`、從不 `activate_ca()`、登入後 `account_balance` 必須是模擬預設值 (同 v1 的三道查核), 任一不過就停止。委託帶 `custom_field="orbv2"`, 和 v1 `paper_trade.py` 共用同一個模擬帳戶也不會讀錯回報。workflow 濾掉 Shioaji 登入時印的 `Session Property` 行 (含身分證字號)。
